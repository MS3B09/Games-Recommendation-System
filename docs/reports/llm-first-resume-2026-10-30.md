## Current implementation changes

1. **Read-only catalog tools.** Recommendation filters apply to that search only. They never mutate saved requirements. The final typed `preferences` object is the only preference write; omitted fields retain previous values, and turn-scoped exceptions do not replace normal conditions. The model must consider an explicit preference object rather than a nullable placeholder. No classifier, input keyword rule or game-specific branch was added.
2. **Separate actions from wording.** After a typed reply plan is validated, the optional final writer receives a smaller `parts`/`game_ids` schema. The server retains the validated memory/preference operations instead of asking the writer to regenerate them and risking silent loss. The original model draft remains in the attempt trace; its unsupported prose is not used as the rewrite anchor.
3. **Local validation of rejected final envelopes.** A provider `json_validate_failed` body containing a proposed conversation answer can reach the same local typed/card/source/filter boundary as normal content. This is untrusted output, not acceptance of a provider error or a hidden HTTP retry. Unknown functions, invented sources/cards, malformed preferences and unexpected writer metadata still fail.
4. **More useful bounded search evidence.** Search still returns its exact scoped page/count. It now supplies a factual preview of the first result, with an explicit preview count; further records/fields remain accessible through `game_details`. Full search coverage is not confused with preview coverage. Filter-only recommendations use the explicitly reported neutral query `games` instead of spending another generation correcting an empty query.
5. **Additional output checks.** Identifier assertions need `app_id` evidence; unseen history IDs cannot act as supplied citations. Dollar/USD amounts and ISO-style dates are checked against cited field values and typed budget context. A temporary budget in a fact reply is allowed as budget context rather than misclassified as a purchase price. These are OUTPUT checks, not input routing. They do **not** prove every descriptive assertion or per-game semantic entailment.
6. **Recorded-price provenance.** If a cited price is mentioned without its actual record date, rendering adds a short deterministic US/USD observation-date context from that price field. It does not generate or replace the amount. Already dated replies are not annotated again.
7. **Relevant detail controls.** A zero description size is accepted when reading other fields, but rejected for a description request so it cannot create a non-advancing description cursor.

Read-only search is the final design. Intermediate v14–v19 approaches that staged or automatically retained tool filters are historical experiments, not current behavior.
